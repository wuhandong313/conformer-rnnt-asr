# Repository Guidelines

## Project Structure & Module Organization

This repository implements Conformer-RNN-T speech recognition on LibriSpeech, with fixed Phone69 labels and offline five-frame/multi-stage compression configurations.

- `conformer_rnnt/` contains the encoder, predictor, joiner, model factories, and Lightning training/data module.
- `conformer_rnnt/compression/` separates frame detectors, mixers, and compression orchestration.
- `train.py` and `eval.py` are entry points; `common.py` provides feature normalization, batching, and decoding utilities.
- `configs/` holds YAML experiment recipes; `scripts/` contains GPU-server pipelines with machine-specific paths.
- `papers/` stores research references; `artifacts/` stores logs, metrics and figures, and `assets/` holds feature statistics. Focused regression tests live in `tests/`.

## Build, Test, and Development Commands

Run commands from the repository root. There is no build step or dependency manifest. The runtime uses `torch`, `torchaudio`, `pytorch-lightning`, `numpy`, `scipy`, and `pyyaml`; Phone69 does not require `sentencepiece`.

- `python train.py configs/server_phone69_460h_offline_native_stride4_none_s42_e50.yaml` starts training after configuring dataset, tokenizer, statistics, and accelerator settings.
- `python eval.py configs/server_phone69_460h_offline_native_stride4_none_s42_e50.yaml --checkpoint /path/to/model.ckpt --cpu --max-utts 10 --out /tmp/eval-smoke.csv` evaluates a small CPU subset using a matching configuration.
- `python -m compileall -q conformer_rnnt common.py train.py eval.py` checks Python syntax without training.

For a short training check, set `trainer.fast_dev_run: true` in a temporary YAML configuration. `eval.py` reports corpus PER for the fixed `tokenizer.type: phone69`. Adapt server pipeline paths before running them.

## Coding Style & Naming Conventions

Use four-space Python indentation, `snake_case` functions/modules, `PascalCase` classes, and `UPPER_CASE` constants. Follow existing type hints and docstrings; use two-space YAML indentation. No formatter or linter is configured.

Keep training options in YAML: `train.py` accepts one configuration path. Keep model factories consistent when adding parameters. `model.num_symbols` excludes the automatically added blank symbol.

## Testing Guidelines

No coverage threshold is configured. Add focused regression tests as `tests/test_<feature>.py` and run them with `python -m unittest discover -s tests`. For compression changes, verify tensor shapes, sequence lengths, preserved right-context frames, and legacy behavior. Run a small evaluation when assets are available; fixed Phone69 configs report corpus PER and mean utterance RTF. The archived corpus RTF protocol is documented in the authoritative evaluation archive.

Run unit, regression, smoke, and other software tests on the local development machine. Do not run tests on the training server; reserve it for explicitly authorized training or evaluation jobs.

## Commit & Pull Request Guidelines

History commonly uses short, imperative messages with prefixes such as `feat(eval):`, `fix(pipeline):`, and `artifacts:`. Follow that pattern and keep commits focused.

PRs should explain the behavior change, affected configuration, validation commands/results, and related issues when applicable. Include before/after metrics or plots for model changes, identifying the dataset, checkpoint, and decoding settings.

## Configuration & Artifacts

Keep credentials in ignored `remote-access.md`. Keep datasets and files larger than 10 MiB untracked. Small logs, scripts and experiment records are synchronized when explicitly requested; runtime caches and environments stay local. Match tokenizer vocabulary and preprocessing settings to the checkpoint, and use distinct experiment/output paths. See `docs/repository_sync.md` for consolidated branches and server paths.

For source code and configuration intended for a server run, use Git to synchronize: commit and push from the development checkout, then fetch/pull the matching branch on the server before launching. Do not deploy code by copying files directly. Keep credentials, datasets, checkpoints, and other large artifacts outside Git according to the rules above.

Synchronize completed changes across the local checkout, Gitee, the GitHub mirror, and the server on the same branch and full commit ID. Keep no non-ignored untracked files except files actively being edited or generated by ongoing work. Identify those exceptions before staging; do not include another active task's unfinished files. Completed small research records referenced by current documentation should be tracked even when their parent directory has a generated-output ignore rule.

`configs/phone69_vocab.json` fixes exactly 69 stressed ARPABET phones (blank ID 69); source noise label `spn` is explicitly filtered during encoding. Phone69 reads external per-chapter `*-ph.trans.txt`; preserve case, stress and spaces. Phone69 SentencePiece configs/checkpoints are no longer supported. Server `train-other-500` uses IPA and cannot join phone69 training. See `docs/phone69_tokenizer.md`.
