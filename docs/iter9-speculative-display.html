一句话总结：iter-9 把 Medusa 从"投机解码的加速器"改造成"投机显示的提前量来源"。 解码回归纯贪心（RTF 不变、零正确性风险），草稿只负责在真实 token 到达前把字先放到屏幕上。 实测发现：瓶颈不是命中率，而是提前量； 而且总命中 90% 里绝大部分来自复制通道（照抄即中）——真正反映能力的是预测区的 43%。
1. 换轨：从「提速」到「显示」价值模型

iter-1 ~ iter-8 一直在优化 验证器接受率——草稿被接受得越多，解码跳步越多，RTF 越低。 但这条路的收益上限受制于 base 模型本身，且每一点接受率都要用复杂的验证器模拟（chain_sim）去换。

iter-9 换了一个问题：如果草稿根本不参与解码，只用来提前上屏呢？

旧模型 · 投机解码（iter-1~8）

  • 草稿进入验证循环，接受则跳步
  • 指标：接受率 / 跳步数 / RTF
  • 猜错 → 验证器拒绝，无副作用
  • 代价：验证器模拟（逐帧扫 joiner）+ 实现复杂度
  • 天花板：受 base 模型精度硬约束

新模型 · 投机显示（iter-9）

  • 解码 = 纯贪心 RNNT，草稿用完即弃
  • 指标：命中率 × 提前量（感知提前量）
  • 猜错 → 屏幕闪烁（上屏后被改写）
  • 代价：闪烁这一个纯感官问题
  • 天花板：窗里能看到多少未来音频
为什么这次换轨是「免费」的：解码路径回到纯贪心后，输出与 greedy oracle 逐 token 一致， 结构上不可能出错（lossless 是免费的）。RTF 不变，也不需要验证器。 换句话说，这是一个可以随时丢弃的增量功能——效果不好就关掉，零风险。

价值模型

value草稿头  =  命中率  ×  平均提前量  −  替换（闪烁）惩罚

提前量以 reduced 帧计 (1 帧 = 4 mel = 40 ms)；命中 = 草稿与随后真实 emit 的 token 相同； 替换 = 上屏后被改写。未命中的草稿提前量记 0（观众看到的是错的，等于没提前）。 所以 value = hit% × mean_lead × 40ms，单位 ms，含义是期望感知提前量。

2. 效果演示：显示时间线仿真可交互

下面用一条 23 帧（920 ms）的合成时间线演示一次显示是怎么发生的。音素串是 /DH AH0 S AH1 N IH1 Z/（"the sun is"，7 次真实 emit）。真实语音按贪心解码在固定帧发射音素； 头在每个 emit 点上立刻草拟下一个音素并上屏。

合成时间线为便于观察做了稀疏化：真实语料的 emit 间隔比这里密， 实测平均提前量只有 33 ms（不到 1 帧）。这里把 emit 间隔放大到 2–4 帧， 是为了让「上屏 → 确认 / 替换」的过程肉眼可见；上屏时机与评分的逻辑与真实系统一致。

从这个演示能看出什么：
  • 上屏与命中无关。草稿在生成的那一刻（如 t=2）就上屏了；是否命中要等真实 token 到达（t=5 / t=8）才判定。 命中率只影响评分，不影响显示行为——所以显示逻辑本身不会因为猜错而失效。
  • 命中 ≠ 提前量。同样是命中，提前量由真实 token 的发射时刻决定： t=2 上屏的草稿在 t=5 被确认，提前量 = 3 帧 = 120 ms。
  • 弃权是免费的。头输出 blank 时不上屏，既不产生错误也不产生闪烁，代价只是没有提前量。 反过来，没命中的草稿会先给观众看错的音素再改回来——这就是闪烁，也是替换惩罚的来源。
3. 系统架构数据流

底座是标准的 Conformer-RNNT（transducer）：编码器把音频压成 40 ms 一帧的声学表示， predictor 维护语言状态，joiner 把两者融合出下一个 token 的分布。 Medusa 头挂在 joiner 之上，不改变底座，只额外预测未来若干帧的 token。

图 1 · iter-9 架构。绿色部分为 Medusa 草稿头（本次唯一训练的部分，base 冻结）； 蓝色为底座编码路径。

三个必须记住的尺寸

量值含义
帧时长40 mshop 160 / sr 16000 × 1000 × stride 4
窗口宽度9 帧1 + past(7) + lookahead(1)
头数1Medusa 草稿头
lookahead 取 1 是保守值，不是物理硬约束：流式块 = 左 64 mel + chunk 16 mel + 右 4 mel， stride 4 ⇒ 一个 chunk 同时产出 4 个 reduced 帧（右上下文不单独压缩，其信息落在 chunk 末帧里）。 因此帧 t 处的零延迟未来预算 = 3 − (t mod 4) ∈ {3,2,1,0}，最多 3 帧、均值 1.5 帧； 只有跨到下一个 chunk 才付真实延迟（≈16 mel ≈ 160 ms）。
当前 [t−7..t+1] 的 look=1 是现有权重训过的保守布局， chunk 对齐的实现可免费用到最多 3 帧未来——代价只是 medusa 要按新窗布局重训。 past 帧在流式部署时已经算好并提交，取它们不花任何延迟，所以 past=7 是免费的。 (注：动态压缩下 mel→reduced 非严格 4:1，3 为标称值，实际延迟按 ms 校核。)

5. 算法细节：头内部到底算了什么medusa.py

Medusa 头是一个加性残差结构：不替换 joiner，而是在 joint 特征上加一个 context delta，再走一遍词表投影。

输入项

predictor = context_predictor(target_enc)          # 语言侧
acoustic  = context_acoustic(窗展平 9×512)          # 声学侧
base_term = context_base_logits(base_logits.detach())  # 验证器分布摘要（detach 防捷径）

草稿 delta

fused = predictor + acoustic + base_term

normalized = context_norm(fused)
delta      = context_mlp(normalized)
           + context_mlp_extra(normalized)         # iter-6 共享深路径

logits     = w_vocab( res_block( joint + delta ) )

所有新增投影均为零初始化（zero-init），所以扩容在 step-0 是无扰动的——这是 warm-start 能跨迭代累加的原因。

诊断工具：两个可选开关

chain_sim（验证器模拟扫描）

在可见窗内逐帧跑真 joiner，问"这个头自己的状态会在这里发射什么 token"。 因为问的是 oracle 自己，所以 once found，读出的 token 一定正确——这是复制通道，不是预测能力。

iter-9 显示模型下已关闭（chain_sim: false），保留仅用于诊断。

--no-sim（纯预测模式）

扫描照跑（诊断标签照出），但不注入读出结果。 头被逼回自己的预测路径，用来分离"复制刷出的命中率"与"真实预测能力"。

副作用：弃权行为改变会让样本集自选择，no-sim 与 sim 模式的数字不可直接比。

区域拆分（本轮的核心里程碑）：一条草稿若 sim found = True，说明答案在可见窗内， 头只要照抄就能命中（复制区）；若 found = False，答案在窗外，头必须真预测（预测区）。 总命中率被复制区占比主导，所以 90% 这个数字是虚高的——看能力必须看预测区。

命中率的分解公式

hit%  ≈  覆盖率 × ≈100%  +  (1 − 覆盖率) × 43%

覆盖率 = 答案落在可见窗内的概率（由 lookahead 决定）；43% 是窗外预测的命中率。 这个分解把"瓶颈在窗内可见的未来帧数"这件事写成了算术。

7.2 提前量分布

P50 = 40 ms（1 帧）、P90 = 80 ms（2 帧）、P99 = 120–160 ms。两个配置分布一致 —— 说明提前量几乎完全由发射密度决定，而不是由窗口大小决定。

7.3 三条结论

① 流式预算几乎不亏

lookahead 8 → 1，命中率只掉 4.2 pt。 iter-8 曾据此怀疑"信息守恒"结论，现确认流式不是主要矛盾。

② 瓶颈是提前量，不是命中率

mean lead 只有 33 ms ≈ 不到 1 帧。 命中率再高，观众也只提前了不到 40 ms 看到内容 —— 这是当前方案的真正天花板。

③ 重训"流式合法头"收益很小

配置 A 是非流式的天花板（94.81），配置 B 已经在 90.60 的位置。 原计划的阶段 2 重训能拿回的边距很有限。

7.4 扫描诊断（chain_sim 推理端，配置 B）

scanfound%simRight%copied%
837085.72100.0099.79

found% = sim 扫描在可见窗内问到了答案（= 覆盖率）；simRight% = 问到的就是目标（问的是 oracle 自己，found 时必为 100%）； copied% = 直注查表被点亮的比例，≈100% 说明复制电路通畅。

命中率上限由覆盖率锁定：按 hit% ≈ found% × ≈100% + (1 − found%) × 43% 估算， 上限 ≈ 85.72 + 14.28 × 0.43 ≈ 91.9%（实测 90.60，已接近饱和）。 想再往上，只能扩大覆盖率或提高窗外的 43%。

7.6 预测能力是「窗内未来帧数」的函数（配置 A，lookahead=8）

同一机制、同样没有复制通道，只是窗从 1 帧放宽到 8 帧：43% → 95.94%。 这就是"瓶颈在窗里能看到多少未来音频"的直接证据。

7.7 门控显示：零训练成本的改进

只在 sim found 时上屏（扫不到就弃权不显示）。不改模型、不重训，直接改推理策略：

闪烁 before → aftervalue before → after
9.4% → 0%30.3 → 28.3 ms

代价：弃权比例提高（found 之外一律不显示），value 从 30.3 降到 28.3 ms。 这是"用提前量换稳定"的取舍，是否值得取决于产品对闪烁的容忍度。

7.9 两个 bug 修复（影响过历史数字）

① warm-start 误删共享 MLP 权重（lightning_module.py:618-660）
过期头键过滤取 medusa_heads. 后第一个数字段，把共享 MLP 的层索引 （context_mlp.2、context_mlp_extra.2/4）误判为过期头索引而丢弃 （BEST_iter7 中范数 97.9 / 76.4 / 40.2 → 丢弃后回落零初始化）。 改为只在 per-head ModuleList 下读索引。iter-8 与 iter-9 首次基线都中了这招。
② 布局错配的假基线：BEST_iter7 的 context_acoustic 是 (512, 4608) = 9 列， 但语义是 iter-2d 解除流式后的 [t..t+8]（past=0, lookahead=8）； iter-8 的流式布局才是 [t−7..t+1]。同宽不同义 —— 用 iter-7 权重跑 past=7 布局实测仅 47.91%，与日志的 0.920 严重不符， 这就是上表里的配置 C，数字无效。
8. 结论与下一步Takeaway
  1. 投机显示是一个零风险增量功能：解码不依赖草稿，猜错只影响观感，不影响正确性。RTF 不变。
  2. 价值模型必须看"预测区"：总命中率会被复制通道污染；90% 是虚高。
  3. 当前瓶颈是提前量（≈33 ms，不到 1 帧），不是命中率。命中率已经 90.6%。
  4. 提升命中率的唯一有效杠杆是"窗内可见的未来帧数"：lookahead 1→8 让预测区命中率从 43% 跳到 95.94%。
  5. 加长过去窗是零延迟杠杆，但它能否把 43% 提上去尚未验证——这是下一步该做的实验。
  6. 门控显示（只在 found 时上屏）是免费的取舍旋钮：闪烁大降，代价是提前量下降。
下一步建议：先跑"加长过去窗"消融（零延迟、只重训 medusa）， 验证 43% 这个常数是否随过去窗变长而上升。若不上升，再用 chunk 内零延迟预算把 lookahead 扩到最多 3 帧（按新窗重训 medusa）。
