删掉声学窗，把序列建模搬进草稿头

头不再拥有自己的声学窗——解码到哪一帧就条件于哪一帧的 enc[t]； 序列上下文是 encoder 注意力的职责。能力增强转向 draft 侧可训练的 因果序列模型（transformer），并用 BNT 蒸馏直接蒸馏验证器的发射决策。 本页解释动机、架构、对齐律、损失、推理 cache 与观测锚点。

一句话总结：iter-9 诊断出三个数字——预测区命中 43% 常数（与头容量无关）、 LM 先验仅 2.18%、弃权率 59%。iter-10 的回答： ① 声学窗是 iter-8 的补丁，删掉，让头直读 enc[t]（上下文感知还给 encoder 的 chunk 注意力）； ② 序列建模搬进 draft 侧（3 层因果 transformer，token 历史 → 因果隐藏态，零初始化注入）； ③ 用 BNT 蒸馏把「验证器 ≤4 帧内会发射什么」直接教给头——训练目标即接受事件本身。
1. 动机：三个诊断数字与一个架构反思iter-9 → iter-10

iter-9 的 100 样本 eval_display（tag disp）给出三个关键诊断：

① 命中率是常数

预测区命中率 h1 43.01% / h2 42.85%——两个头几乎一样。 说明瓶颈不在头容量，加多少参数都无效；必须换信息源或换序列建模方式。

② LM 先验几乎不可用

纯语言先验基线只有 2.18% / 0.64%。头依赖的 frozen predictor 只有 2 层×128 LSTM，从未被训练成好 LM——头的「语言外推」地基是软的。

③ 弃权率高达 59%

头没学会「何时开口」：59% 的草拟轮直接输出 blank 弃权。 弃权免费但零收益——敢不敢说和说得对不对同样重要。

架构反思：头不该有窗

旧架构 · 9 帧锚定窗（iter-8）

  • 头自带 [t−7 … t+1] 锚定窗，展平 9×512 后投影
  • 窗是 iter-8 的补丁：为了流式合法，用过去帧换未来帧
  • 训练/推理双路径开窗，曾是 bug 温床（T=1 二次开窗清零 lookahead 列）
  • context_acoustic 输入 4608 维，冷启动笨重

新架构 · 单帧直读（iter-10）

  • 解码到哪一帧就条件于哪一帧的 enc[t]，宽度 1
  • 窗是 encoder 注意力的事：上下文感知是 Conformer chunk 注意力 （left/segment/right context）的职责，不该在头上复制一份
  • _anchor_window / context_acoustic / win_attn 整体删除
  • 腾出的预算投给 draft 侧可训练序列模型（表达力上限更高）
范围约束：base（encoder + predictor + joiner）完全不动、只训头（freeze_base: true）。 加性规则保证注入通道不碰 base 数值；零初始化保证 warm-start 的 step-0 与旧头逐位等价。
2. 系统架构：五项加性融合数据流

底座不变。变化全部发生在绿色的 Medusa 头内部：声学侧从 9 帧窗换成单帧直读， 新增一条 draft 侧因果 transformer 通道吃完整 token 历史，最终与原有通道加性融合。

图 1 · iter-10 架构。黄色为加性融合的可训部分；绿色为头与损失； 蓝色为底座编码路径。两个新增注入通道（draft_state_proj / acoustic_frame_proj）均零初始化， step-0 与旧头逐位等价。

三个必须记住的尺寸

量值含义
头输入宽度1 帧enc[t:t+1]，宽度 >1 直接 raise（窗概念已删除）
transformer3 层 · 9.5Md=512 / 8 头 / FFN 1024 / pos ≤4096；可切 4 层×256 LSTM（2.4M）
头数2h1/h2 链式草拟，warm-start 自动丢 medusa_heads.2.*
为什么声学信息用加性注入而不是 cross-attn：训练网格是 (B, T帧, L语言位) 的三维张量， 时间轴与语言轴之间没有 t↔l 对齐，对 enc 全序列做 cross-attn 会泄露未来帧。 acoustic_frame_proj(enc[t]) 按帧对齐加性注入，既无泄露又零初始化安全。
3. 对齐律：三条通道共享的不变量最易错处

整页最关键的一张卡。所有条件/对齐通道都落在同一条律上，错一列训练就静默失效：

head-k（k = 1..K）在网格列 l 条件于「消费完 yl+k−1 的状态」， 预测 yl+k

记号：TF 网格列 l 对应 predictor 状态 g_l（prep = [BOS, y_1..y_U]， g_0 = 仅 BOS）；post-emit 语义下验证器从状态 gl+k−1 出发发射的下一个真实 token。

三条通道逐一核对（同构移位切片）

# ① LSTM 通道 (原有): rolled 状态切片
rolled[k_idx] = pad(tgt_enc, K)[:, k_idx : k_idx+L]     # k_idx = k−1, 0-based

# ② transformer 通道 (新): 因果隐藏态的同构切片
h_seq = seq_model.forward_full(prep)                     # h_seq[m] = 消费完 prep[m] 的状态
rolled_hidden = pad(h_seq, K)[:, k−1 : k−1+L]            # 与 ① 完全同构

# ③ 推理: emit y_u 后 head-1 吃 u+1 个 token (含 BOS) 的隐藏态起草 y_{u+1};
#       head-k 吃 y_u + 已接受 d_1..d_{k−1} (共 u+k 个)  ⇒ 恰为 TF 列 l=u 的条件
chain_hiddens[k] = seq.forward_step(d_{k−1})             # KV cache 增量, 与 TF 全序列逐位一致
同构性是结构保证，不是约定：冒烟测试 5 在随机权重下断言「全网格某 (t,l) 的输出 == 单点推理（cache 吃同前缀）」，transformer 与 LSTM 两条实现都过（atol 1e-4）； 测试 6 断言「cache 增量 == 全序列、回滚后 == 全新 cache」。 TF/推理不同构的 bug 在这条测试下无处藏身。
历史教训：iter-9 里 kl_to_base_loss 调用漏传 chain_align=True， 默认 False 会把 head-k@l 对到 base 列 l+k——错一列。权重为 0 所以当时无影响， iter-10 接线时已修正（即使权重 0 也用正确口径）。
4. 损失设计：蒸馏「接受事件」本身BNT
loss = RNNT (1.0, 不经头) + Σk wk·CEk [0.8, 0.64] + 0.1·LM_aux + 0.2·BNT (+ 0·KL)
损失权重监督什么攻击哪个诊断数字
shifted_ce[0.8, 0.64]head-k 在列 l 预测 y_{l+k}（ground truth）43% 常数（主头损失）
LM_aux 新0.1纯 token 侧 next-token CE：w_vocab(draft_lm_proj(h_seq[l])) → y_{l+1}，w_vocab 冻结LM 先验 2.18%（给 transformer 独立于声学的监督）
BNT 接线0.2蒸馏「验证器从这个状态出发 ≤4 帧内的发射决策」弃权 59% + 提前量
KL0保留不启用（与 CE 目标冲突，iter-1 结论）—

BNT 的监督时机分布（与 shifted_ce 的关键差别）

# BNT 标签 = base_ids[t..t+4, l+k−1] 中首个 non-blank argmax  (= 验证器的实际决策)

δ=0 帧  验证器立即发射     → 教头「现在就说这个」        → 治弃权 (59%)
δ=1..4  验证器先走 blank   → 标签穿透 blank 看到未来的 token
                            → 头学会「快到了, 提前上屏」   → 提前量来源
found=False (句尾)         → 无损失、无 NaN               → 监督自动集中在 emit 事件附近

与 shifted_ce 的互补

shifted_ce 在所有 t 帧均匀监督——包括 token 很远的帧，头被迫永远在猜； BNT 只在「验证器 ≤4 帧内真的会发射」的位置产生监督。监督分布自动对齐草拟发生的时刻。

潜在冲突与缓解

BNT 的标签是 base 的实际 argmax（含 base 的错误），shifted_ce 是 ground truth—— 两者可能打架。缓解：权重从小起（0.2），观察两条 loss 曲线；冲突则降权（扫描 0.1 / 0.5）。

梯度流审核（加性规则）：base_term detach、k≥1 的 draft embed detach、 encoder/predictor/w_vocab 冻结、RNNT 不经头 ⇒ 梯度只落头侧。 LM_aux 经冻结 w_vocab 只回传 proj + transformer； 零初始化输出投影（context_mlp[-1]、res_blocks.linear2）是 step-0 的 bootstrap 入口， 一步更新后上游（acoustic_frame_proj / draft_state_proj / seq 模型）梯度可达—— 这是标准零初始化 bootstrap 语义，冒烟测试 1 显式验证。
5. 推理时序：seq cache 的快照与回滚可交互

草拟时 seq cache 总是随 draft 推进（这样全接受时零开销）；验证结束后对账—— committed 与 appended 不一致才回滚到快照并重放已提交 token（纯 token 侧，回滚 = 截断，O(1)）。 下面一步步走一遍两个典型回合：

步骤 0 / 0

■ 本步 append · ■ 回滚后重放 · ■ 被丢弃的分支 · ┄ 黄框 = 快照边界

按「播放」或「单步」开始。
无损性没有被破坏：回滚重放的只是 seq cache（草稿侧记忆），验证器的状态推进 （predictor rolled 状态）仍严格复刻 greedy oracle——投机输出与贪心输出逐 token 一致 （冒烟测试 2 / eval.py 双重验证）。回滚只在部分接受/失配时发生； 全接受（committed == appended）直接免回滚，这是设计的快路径。

8. 结论与下一步Takeaway
  1. 窗死了：头的声学输入收敛到单帧 enc[t]；上下文感知回归 encoder 注意力的职责。 推理路径变简单（无窗拼装），一类历史 bug（T=1 二次开窗）从结构上消失。
  2. 序列建模搬进 draft 侧：3 层因果 transformer 吃完整 token 历史，经零初始化 draft_state_proj 注入——加性规则下 base 数值零扰动，warm-start 安全。
  3. BNT 蒸馏 = 训练目标即接受事件：监督时机自动集中在 emit 附近， δ=0 治弃权、δ>0 给提前量；与 shifted_ce 互补且有权重旋钮。
  4. 对齐律是唯一不变量：三通道同构移位切片，冒烟测试逐位断言；错一列即静默失效（kl 的历史教训）。
  5. cache 回滚是 O(1) 纯 token 侧操作，无损性由对账机制保证；全接受走免回滚快路径。
  6. 下一张牌：overall 逼近 85 后，iter-11 叠加 chunk 对齐 lookahead 2–3（零延迟预算 3−(t mod 4)）冲 90%。
