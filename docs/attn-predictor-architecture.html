受限因果注意力 Predictor（v2）：定位、根因、修复与训练出数

把 RNN-T 的 LSTM predictor 换成受限因果自注意力 trunk（Family A · MSA-Transducer 风格， arXiv:2102.11594）。原版（8 月初）从头训练两天即弃——本页先讲清为什么训不动 （探针实测定位到三个叠加根因），再讲 v2 怎么修：位置编码、pre-norm、 绝对位置入 state、独立 LR 组；最后是 120 epoch 从头训练的实际结果 与两个解码期 bug（forward 忽略 state、变长 KV 过不了 beam 批处理）的修复。

一句话总结：RNN-T 的 predictor 是纯语言侧模块（无声学输入），原版注意力 trunk 训不动不是「注意力不行」，而是三个叠加根因——无位置编码（分不清同 token 最近一次出现）、post-norm 从头训练收敛慢、13× 参数与 0.34M 的 LSTM 同一配方。v2 逐一修复后从头训练 120 epoch 收敛 （val_loss 18.37 @ ep42），beam-20 全量 test-clean PER 0.1069——与 iter-10 从头训练持平（0.1077），仍落后 warm-start LSTM 基线（0.073）。
1. 定位与契约：predictor 是什么、不是什么Family A

PredictorAttn 替代原 LSTM Predictor，作为 RNN-T 验证器的 自回归语言 trunk。它没有、也不该有声学输入——上下文感知是 encoder（Conformer chunk 注意力）的职责；声学与语言只在 Joiner 处加性相遇。

保持不变的契约

  • forward(input:(B,U), lengths, state) → (out, lengths, state)，输出 (B,U,512)，与 Joiner 加性融合兼容
  • predict(input:(B,1), lengths, state) 逐 token 增量——torchaudio 2.6 RNNTBeamSearch 把 state 当不透明对象穿线、不查内部结构（已核对源码）
  • embedding 行数 = num_symbols+1（blank 挂末位），与原 Predictor 一致

本迭代变化：trunk 内部 + 解码接口

  • LSTM [h, c] → 注意力层 [K, V, P] 三元组（同型不透明 state）
  • 受限因果窗 left_context：query 只看 [i−L+1, i]；训练用 1024 ≈ 全因果，流式收紧
  • 解码接口：forward 带状态单步委托 predict（§7 修复①），KV 定长循环 cache（§7 修复②）
  • 其余组件（encoder / joiner / 训练管线）零改动

3. 为什么原版训不动：探针实测的三个根因8 月初事故复盘

原版 trunk（无位置编码、post-norm）8 月初从头训练，与 LSTM 同配方跑两天即弃。 复盘时用合成探针任务定位根因——不用等一次真实训练（数小时）才能归因。

① 无位置编码

自注意力对 token 集合置换不变——分不清「同 token 最近一次出现在哪」。 RNNT 词表大量 repeat（单词内重复、屈折），repeat 命中探针 0.39 vs LSTM 0.54。

② post-norm 从头训练收敛慢

norm 在残差之后，深层梯度路径不稳。v2 改 pre-norm （iter-10 的 DraftCausalTransformer 同款结论），warm-in 显著加快。

③ 配方错配

3.33M vs 0.34M 参数（13×），却套用同一组超参 （LR 5e-4 / warmup 10k / 120 epochs）从头训练，两天未见反超即弃。

探针设计与结果

任务：bigram Markov 链（V=74，每状态 6 个随机后继）+ 18% 立即重复；SEQ=48。 unigram 下界 CE = 4.213。v1 探针（i.i.d. 任务）曾给出误导性结论——两个 trunk 都收敛到 unigram 常数 2.92，任务太弱没有区分度；bigram + 重复才有。

4. v2 修复与等价性不变量逐根因对症
根因修复实现要点
无位置编码pos = Embedding(max_len=4096) 加性注入_embed(tokens, start_pos) 统一入口；full 前向 start_pos=0，增量 start_pos=state 中的 P
窗口 ≠ 位置P 入 state：[K, V, P]，KV 定长循环 cacheK/V 恒为 left_context 长，新 token 写槽位 p % left_context（覆盖最旧），有效性掩码由 p 推导（age ≤ p）；P (batch,) 逐行携带绝对位置。定长是 beam-search 批处理的前提（见 §6）
post-norm 收敛慢pre-norm（norm 进残差分支）x + Dropout(MHA(LN(x)))；尾部补 final_norm 保输出尺度

等价性不变量（smoke_attn.py 逐位断言）

full 前向 (B,U) 逐位 == 增量 predict 逐 token（KV cache 吃同前缀）——含 left_context 截断区间

这条不变量是结构保证而非约定：增量路径每个 token 的 K/V 在被处理时已烧入它的绝对位置， 循环槽位上的有效性掩码恰好复现 full 路径的受限因果窗；P 逐行推进、永不回退（除回滚）。 任何「TF/增量不同构」的改动都会被测试当场抓住——与 iter-10 对齐律的冒烟测试同一思路。 实测：真实 ckpt 权重下 full vs incremental 最大偏差 5e-6（CPU/CUDA、U=600）。

梯度通路：pos embedding / attention / FFN / 输出头全部可训练； P 是 long 常量（不参与梯度）；left_context 截断只影响推理增量路径， 训练全序列路径用 mask 表达同一窗口——两条路径 mask 语义逐位一致由测试 1/2 保证。

等价性的来源：每个 token 的 K/V 在被处理时已由「embedding + 它当时的绝对位置」算出—— 位置信息烧在 cache 内容里，所以循环槽位覆盖最旧不需要重算幸存 token；有效性掩码 （age = (p − s) % L ≤ p）恰好复现受限因果窗。P 只需要告诉 新 token 它是谁的第几步。这就是为什么「定长循环 KV + P 照常推进」与全序列前向逐位等价。 回滚时 P 必须与 KV 一起恢复——被拒的 draft 没有被消费，位置也要退回。

7. 解码期修复：forward 委托 + 定长循环 KV cache训练正常 · 推理触发

训练收敛、全量评估却在出垃圾（首位 token 无限循环）——两个 bug 都只在 解码路径触发，等价性冒烟测不到（它们不在 trunk 内部，而在 trunk 与 解码器的接口上）：

Bug现象根因修复
① forward 忽略 state 贪心解码每步 logits 恒定（如 73:−0.72 不动），首位 token 无限循环 torchaudio beam-search 的 decode 契约是 model.predict → predictor.forward 带状态单步。LSTM 的 forward 恰好天然单步，attn 的 forward 却把 (B,1) 当全序列重算——末 token 每重新 embed 在位置 0，无历史 forward 收到 state 且输入单步 (B,1) 时委托 predict() 走增量路径；训练路径（state=None）不变
② 变长 KV 过不了 beam 批处理 beam-20 直接 RuntimeError: cat 尺寸不匹配（原 device-side assert 同根因） torchaudio 在同一帧内对 a-hypo 续扩：不同 hypo 消费的 token 数不同， KV cache 长度互异（实测 20 vs 22），_batch_state 沿 batch 维 cat 失败 定长循环 KV cache：K/V 恒为 left_context 长，新 token 写槽位 p % left_context；有效性掩码由 p 推导 （age = (p−s) % L ≤ p）；P 改为 (batch,) 逐行携带绝对位置。 cat / index_select 全程成立，torchaudio 内部零改动
逐位等价保持：循环槽位上「age ≤ p」的掩码恰好选出绝对位置 ∈ [p−L+1, p] ∩ [0, p] 的 key 集合——与 full 路径的受限因果窗严格同构。 修复后单条 e2e trace 从 3998 次重复发射恢复为 90 次合理发射； 全量贪心 PER 从「垃圾」恢复到 0.1112。
教训：等价性冒烟测试只覆盖「trunk 内部」的 full vs incremental， 没覆盖「trunk × 解码器」的接口语义（forward 带 state 的单步契约、 批处理 state 的形状假设）。smoke 已补三类用例：混合 token 数 hypo 批处理等价、index_select 切片续解码、P 逐行正确性。

9. 结论与下一步Takeaway
  1. 归因先行：合成探针（bigram Markov + 重复）两天内把「训不动」拆成三个可修的根因， 避免在真实训练上盲试——i.i.d. 探针太弱的教训是任务必须有 recency 区分度。
  2. v2 = 位置 + pre-norm + 配方，训练可用：从头 120 epoch 收敛 （val_loss 18.37 @ ep42），beam-20 全量 PER 0.1069——与 iter-10 从头训练（0.1077）持平， 验证了注意力 trunk 在本任务上的可行性；但距 warm-start LSTM 基线（0.073）还差 3.4 pt。
  3. 接口 bug 只在解码路径暴露：训练/TF 全程正常，垃圾输出全部来自 forward 忽略 state + 变长 KV 过不了 beam 批处理——冒烟测试必须覆盖 「trunk × 解码器」联合语义，而不只是 trunk 内部等价性。
  4. 契约零破坏：对 torchaudio beam-search 而言 state 仍不透明， 定长循环 cache 让 cat/index_select 语义成立，torchaudio 内部零改动。
  5. 下一步：① 在该 trunk 上接 Medusa 头，评估其作为草稿骨架的接受率 （Family A 路线的既定用途）；② 消融 left_context 与 predictor_lr_scale（0.5 → 1.0 weight-only 重启）尝试缩差距； ③ 训练 60 epoch 即可（ep42 后过拟合）。
