# 如何证明新方法优于旧方法：跨领域论文与本项目实验方案

日期：2026-10-29（Asia/Shanghai）。本文件是文献调研和实验设计建议；没有启动训练、评测或修改模型。已有结果均引用本地记录，不是本轮重新测量。研究重点是公平比较与证据设计，不是汇总语音或压缩算法。

**核心判断：同参数量只能排除一种解释。应先确定想证明的主张，再设计能够区分“方法机制、模型容量、训练机会、计算预算和随机波动”的对照。实验应允许主张被否定。**

**2. 顶会标准与本报告建议的区别**

[NeurIPS官方checklist](https://neurips.cc/public/guides/PaperChecklist)要求/询问主张范围、可复现路径、数据划分与调参细节、主要实验的不确定性及计算资源，并要求明确误差条捕获的变异来源。它允许对无法完成的项目作出解释，没有统一规定“所有模型必须同参数”或“每个实验必须三个/五个seed”。

[NeurIPS 2026评审指南](https://neurips.cc/Conferences/2026/ReviewerGuidelines)关注技术质量、清晰性、意义和原创性；[ICLR 2027评审指南](https://iclr.cc/Conferences/2027/ReviewerGuidelines)关注问题、动机、证据与新增知识，也明确不以是否达到SOTA作为唯一依据。实验完备不能替代问题价值和原创性，也不存在保证录取的实验数量。

以下四组对照、推荐重复次数和执行优先级都是针对本项目的研究设计建议，不是会议统一硬性规定。

**3. 当前项目已经控制了什么，仍有哪些差异**

参数数来自[五帧运算记录](../phone69_460h_five_frames_computation_20261018.md)，不是本轮实例化模型重新统计：

| 设置 | 总参数 | 与stride4_none差值 |
|---|---:|---:|
| stride4_none | 4,207,942 | 0 |
| stride1 + five_frames，第2层后 | 4,236,299 | +28,357（约0.674%） |
| stride2 + five_frames，第2层后 | 4,231,179 | +23,237 |
| stride4 + five_frames，第2层后 | 4,228,619 | +20,677 |

各组Conformer内部宽128、层数10、头数8、FFN512等主干规格一致，但总参数不同。输入投影为80→128/stride，因此stride1相对stride4多7,680个投影参数；五帧融合器另有20,677个参数。

源码`LearnedWeightMixer`在128维、隐藏宽32时：diff5是4→32→5，共325参数；five_frames是640→32→5，共20,677参数；nine_frames是1152→32→9，共37,193参数。五帧比diff5多20,352参数；九帧比五帧多16,516参数。若主张是某一种权重预测方式更好，还需区分输入信息、窗口范围和容量的作用。

[已完成四组评测记录](../phone69_five_frames_testclean_results_20261021.md)中，各组50epoch的更新数为56,900、126,550、59,850和48,550。stride1动态组约为基线的2.224倍更新。`warmup_steps=10000`、按步验证和`RNNT reduction=sum`会使批次差异同时影响学习率进程、选模机会和梯度尺度。因此，同epoch不能推出同优化条件。

[研究优先级记录](../phonetic_compression_research_priorities_20261028.md)和2026-10-27压缩统计中，第5层方案PER为4.7809%，基线为6.1284%，观察到相对下降约21.99%。但第5层前五层处理完整长度，最终保留39.44%原Mel帧，基线最终保留25.05%；该结果没有单独证明等计算优势。位置组与原四组的解码设备也不同，正式比较应统一。

原四组RTF在最多四个任务共用A100时获得，不能作为独占GPU的正式速度排名。CPU帧数复算的elapsed_seconds也不是统一、隔离后的完整推理速度。

**4. 先固定要证明的主张**

| 主张 | 应有的关键比较 | 单独不够的证据 |
|---|---|---|
| 自然峰谷位置有价值 | 同层、同融合器；共享表示和逐句K的机制对照 | 对比更早的固定stride |
| 输入条件融合有价值 | 同选点下等权/全局可学习权重/条件权重，并报告容量 | 完整模型优于无模块 |
| 压缩位置影响信息保留 | 同协议比较层位，并记录逐层长度与成本 | 仅展示test最优层 |
| 相同资源下质量更好 | 对齐所宣称的资源：参数、训练计算或推理时延 | 仅对齐隐藏宽度 |
| 相同质量下更高效 | 成本—质量关系及开发集预定的质量容忍范围 | 帧数更少或差异“不显著” |
| 无目标率分配适应输入 | 自然K与定比例/打乱预算等负对照 | K会变化，或平均约40% |
| 普遍有效 | 与范围相称的独立数据、语言、骨干和训练重复 | 一个seed、一个测试集 |

资源匹配不是把所有条件强行同时锁死。机制实验、等预算实验与各方法充分调优的系统比较，应分别命名和解释。

**5. 最关键的四组：选点 × 融合**

在开发集确定同一个压缩位置、同一个stride、同一个骨干和共同训练协议后：

| 编号 | 中心位置 | 融合 |
|---|---|---|
| U-M | 均匀 | 同一五帧窗口，边界有效帧等权平均 |
| U-L | 均匀 | 当前five_frames MLP |
| N-M | 自然峰谷 | 同一五帧窗口，边界有效帧等权平均 |
| N-L | 自然峰谷 | 当前five_frames MLP，即本方法 |

- N-L与U-L比较：融合器参数相同，检验选点规则。
- N-M与U-M比较：在简单融合下复核选点作用。
- N-L与N-M比较：检验增加可学习条件融合的系统收益，但同时增加容量，不能单凭这一对声称已排除容量解释。
- U-L与U-M比较：检查可学习局部融合是否对普通均匀中心同样有效。

可用`(PER_NL - PER_NM) - (PER_UL - PER_UM)`描述交互；必须说明PER尺度、匹配条件和不确定性。四组端到端表示若不同，该量是该系统设置下的交互，不能解释为纯粹的选点位置因果效应。

等权平均必须覆盖同样的局部五帧窗口并使用同样的边界有效性处理；当前`seg_avg`按相邻中心定义区间，不能直接改名为mean5。各组padding、长度传播、尾部补齐与离线语义也应一致。

**6. 把“保留多少”与“保留哪里”分开**

机制诊断：从一个共同的、在训练数据上训练的冻结前缀提取表示H；对每句由自然检测器得到K；再用同一H和同一K分别构造自然、均匀和随机中心。三个条件均保留时间顺序；随机位置应多次采样。可以训练各自下游部分，但前缀必须持续共享且冻结，训练与测试均采用各自对应规则。

这样才能真正让逐句K和上游表示一致，缩小位置机制的替代解释。它是机制诊断，不是原端到端系统性能的替代品；从一个新方法模型直接在测试时替换中心，还包含分布偏移，只能作为补充敏感性分析。

端到端系统比较：均匀采样率、已有方法阈值等只在dev校准，覆盖本方法附近的输出长度和真实成本；锁定后完整训练与测试。报告实际匹配误差。不同模型即使平均保留率相同，也不能声称逐句K相同。主方法仍不需要增加keep_rate。

**7. 基线应覆盖的范围**

| 基线/对照 | 用途 | 优先级 |
|---|---|---|
| 保存的stride4_none | 已有系统参照，保持记录完整 | 直接保留 |
| 共同协议下的stride4_none | 若主张相对它的受控改善，用于消除训练协议差异 | 与该主张绑定 |
| stride1不压缩 | 检验高时间分辨率本身能达到的质量和成本 | 核心参照 |
| U-M、U-L、N-M、N-L | 拆解选点与融合 | 核心 |
| 最相关且可适配的已发表强方法 | 建立竞争力；统一数据、骨干、监督和解码 | 方法优越性主张需要 |
| 随机中心、全局可学习五权重 | 排除简单替代解释、分析条件性 | 机制增强 |
| 有效的容量对照、五/九帧宽度扫描 | 区分增加参数和增加上下文 | 容量/窗口主张需要 |

stride1无压缩只是参照，不能预先称为理论精度上界。旧diff5若作为内部旧版本，须在有效的共同定义下比较；已作废实验不回填进正式表。外部方法适配到本骨干时标明“adapted”，不把不同任务或骨干的论文绝对数字直接拼表排名。

参数报告至少拆为总参数、主干参数和新增模块参数。必要时用实际参与计算的局部MLP/卷积等容量对照，或作宽度敏感性扫描。不要添加不参与前向的虚拟参数。均值融合少参数本身是有意义的比较，不必为了每一行整数相等破坏机制定义。

**8. 共同训练协议与公平调参**

共同协议的主比较固定训练/验证划分、标签和归一化、增强、骨干、有效批次定义、优化器、损失归一化、总数据暴露、学习率进程和选模标准。批次清单与更新边界尽可能共同；OOM时可用微批次累积，并按整个逻辑批次的分母正确归一化。

梯度累积只解决部分问题：如果实现含BatchNorm等依赖物理batch的状态，改变微批次仍可能改变结果。需固定相应设置或明确说明剩余差异。相同seed也不自动保证共有模块权重、样本顺序与增强流相同，应显式核验能共享的部分。

学习率进程可按共同更新或累计见过的样本/音频量定义，重点是与比较目标一致。验证和checkpoint候选按共同数据进度安排，避免小batch模型拥有更多选模机会。主指标可为dev PER；若保留dev RNNT loss选模也可以，但各组须统一并事先固定，不能在看到test结果后切换。

在受控比较之外，可再给新旧方法各自调优后的结果。预先声明调参的主预算（例如同GPU小时，或同数量的完整候选训练），同时报告实际trial数与计算量；两者不必强行相同。旧方法从作者合理方案起步，新方法的层位、窗口和失败探索同样计入研发预算。小预算可先检查学习率等关键项，不必机械照搬大型论文数千次搜索。

若声称训练效率，另做固定训练FLOPs/GPU小时的学习曲线；同50epoch的质量实验不能自动支持这一主张。达到同一质量的时间应使用同样验证频率、预定阈值，并计入验证开销或明确计时边界。

**9. 统计证据：两个层次分别报告**

测试抽样层：以`ΔPER = PER_new - PER_old`为主效应，负值表示新方法错误率更低。对同一speaker的全部句子作为cluster，配对重采样speaker，例如5,000–10,000次；每次对两个模型采用相同的抽样索引，重新计算各自总错误/总参考phone，而不是平均逐句PER。报告差值和95%区间、重采样单位、次数和假设。

训练随机层：只有一个checkpoint/seed时，上述区间是条件于这两次训练的测试抽样区间，不能称为跨初始化稳定。若以后扩展，优先在主方法、最强基线和关键对照上增加配对seed；可先3次评估方差，必要时更多，数量取决于效应与方差而非统一规定。报告全部运行和均值、标准差；多个epoch的checkpoint不是独立seed。

现有规划将多seed、BPE/WER与第二骨干排除本轮；本报告不改变该范围，将这些列为扩大主张的增强项。保留单seed时应明确结论只覆盖当前训练实例及已测试设置。

不要把189,023个phone当作189,023个独立样本做简单比例检验；同句和同speaker存在依赖。若有多个确认性比较，先规定主比较并考虑Holm等多重比较校正；十档语速通常先作描述性分析，不在大量子组中挑显著行。

差异未显著不能证明两个方法等效。若声称“同精度更快”，预先选定有实际意义的PER容忍范围，并用区间/非劣效思路判断是否满足，而不是看到p>0.05就称为无损。

**10. 真实成本与可复现计时**

对每个主要方法报告：编码器耗时、预定边界的完整推理耗时、峰值显存、FLOPs/MACs约定，以及训练成本。参数量与输出帧数作为辅助指标。

统一硬件、软件版本、dtype/TF32、CPU线程、batch、长度分布、beam和语言模型条件。使用空闲设备，先warmup，再做多轮交替测试。GPU计时须同步或用合适CUDA event；CPU参与和同步等待的总成本需由墙钟计时覆盖。分别报告batch1延迟和批量吞吐，p50/p95及重复测量波动；离线整句延迟不解释为流式首字延迟。

计入检测器、CPU往返、窗口收集、权重MLP、融合、padding/打包和解码。特征提取与数据I/O是否纳入要明示；可分别给模型内部和音频到输出的结果。RTF若使用，区分`总耗时/总音频时长`与`逐句RTF平均`，二者不是同一个统计量。

可用下式说明成本来源，但数值最终需实际测量：

`C ≈ C_prefix(T, layer) + C_detect(T) + C_mix(K, window) + C_suffix(K, layer) + C_decode(K, target_length)`。

批处理还受各句最大有效长度和padding影响。同样平均K/T不保证相同计算或相同时延。压缩后约40%长度也不意味着整个编码器只花40%计算。

新reference/batched后端可单列实现对照：同checkpoint、相同选点与有效长度，检查输出/梯度误差及完整解码一致性，再比较速度。若算法和后端同时变化，分别测量，避免把实现优化全部归因于算法机制。

**11. 自适应与失败条件应怎样分析**

现有单阶段保留率都约40%，应进一步检查逐句分布、候选间距、每秒K、语速、时长、speaker与噪声的关系。相关性不是“找到了语言边界”的证明。

若主张自适应数量有效，可在共同冻结表示的诊断中比较自然K、长度定比例K，以及在相近时长组内打乱K/T的控制；再在完整系统中检查是否转化为收益。若主要作用只是自然位置，论文就聚焦位置，不强写自适应预算。

同句保音高变速能减少跨句内容差异，但仍伴随变速器伪影；全方法用同一变换并报告变换方式。以同一原始speaker/句子聚类统计，不能将各个变速副本当成独立样本。边界/phone标签只用于离线分析，不作为本方法推理的隐藏输入。

保存S/D/I、长短句与快慢语速分组、过度压缩失败和少量代表性可视化。案例事先按规则抽取或同时给成功/失败，不能只挑最漂亮的对齐图。第5层最佳、早期压缩较差本身可能揭示表示深度与信息保留之间的关系。

**12. 独立确认与主张范围**

已多次查看的test-clean继续报告，但不再用于选层和改窗口。之后在dev完成所有选择并冻结代码/config，再在独立测试条件上确认。可用审计通过的phone69 test-other，或既有规划中的中文确认；不能为凑测试集混用IPA与phone69。

中文验证先在英文开发集锁定方法，再检查迁移，不在中文test上重选最好层。AISHELL-3与THCHS-30若联合训练，应分别报告测试结果；两个测试集不是两次独立训练。英语phone PER与中文音节错误率不直接平均。

另一语言支持跨语言主张，另一骨干支持跨骨干主张，多seed支持训练随机稳定性；它们不能互相替代。仅做当前phone69设置仍可形成范围清晰的实证研究，但不能直接声称普遍词级ASR或流式优势。

**13. 推荐执行顺序与论文产出**

1. 冻结主张、主比较与选模规则，汇总现有运行的参数、更新数、硬件和配置差异。
2. 用已有checkpoint统一补充误差分解、配对抽样区间和隔离计时；这些改善描述，但不能事后消除训练协议差异。
3. 在dev确定的层位，以共同协议完成U-M/U-L/N-M/N-L；本方法也要纳入共同协议。若宣称相对stride4的受控提升，stride4也要有对应确认运行。历史基线不覆盖。
4. 补stride1不压缩和最相关外部强基线；预算有限时，先验证U-L与N-L的关键差异，再决定后续投入。
5. 做共享表示/逐句K的机制诊断以及成本—质量关系；视证据决定是否继续五/九帧、全局权重和自适应数量对照。
6. 锁定最终方法后做独立数据确认；训练重复与第二骨干按扩大的主张和资源决定。

主文建议包括一张共同协议的竞争结果表、一张四组机制表、一张成本—质量图、一张有区间的主要效应图，以及一张能覆盖失败条件的机制图。附录记录超参数、搜索、逐层长度、计时细节和复现实验清单。表图数量不是录取标准，证据可以合并展示。

每次运行至少保存：实验ID、代码commit及未提交diff指纹、config哈希、数据/标签/词表版本、总参数与模块参数、数据顺序/seed、有效与物理batch、更新数及见过的数据量、学习率/损失/裁剪、验证进度与选模标准、checkpoint哈希、逐句预测和S/D/I、逐层长度、硬件软件和完整计时边界。搜索失败与预算耗尽的运行也保留。

**14. 预先规定如何解释负结果**

- U-L与N-L接近：峰谷选点的独立贡献不足，优先研究延后降采样与局部融合。
- N-M与N-L接近：条件MLP的必要性不足，简单均值方案可能更有实际价值。
- 五帧与九帧差异被容量对照解释：不能将提升全部归因于更长上下文。
- 共同协议后收益消失：历史优势可能来自训练条件或其交互，不能继续按纯算法优势叙述。
- 第5层质量更好但同质量成本无优势：可定位为表示/分辨率研究，不宣称已实现更高效率。
- 多seed或独立测试不稳定：报告适用范围与失败条件，而不是只留下最佳运行。

论文的目标是建立可被检验、范围准确的知识。强对照和负结果能决定应该保留哪条贡献，也能避免继续花算力验证错误的解释。
