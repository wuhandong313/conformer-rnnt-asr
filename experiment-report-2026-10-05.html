动态帧压缩语音识别实验：计划与进度报告

日期：2026-10-05 ｜ 项目：Conformer-RNNT 动态帧压缩（attn-predictor）｜ 训练与评测均在 GPU 服务器自动管线完成
研究目标（一句话）：在 Conformer-RNNT 语音识别模型中做动态帧压缩——编码器自动找出"信息变化小"的语音帧并跳过，目标是大幅降低编码器计算量（约 3.7 倍），同时不掉识别精度。 方法上解耦两个正交维度并做矩阵式消融：检测器（判断哪些帧重要：raw / savgol / cosine_diff / cosine_diff+savgol）× 混合器（丢帧信息如何补偿：hard 硬选帧 / seg_avg / learned 可学习加权）。

一、实验计划（5 批次，约 260 GPU·小时）

二、核心结果

1. 压缩率锁定：保留 27% 的帧（r=0.27）

诊断实验确认语音帧间冗余度高，27% 保留率是质量与计算的平衡点，全管线统一采用。

2. 消融配置说明：检测器与混合器具体是什么

15 组实验共享同一套管线与口径：检测器给每帧打"重要度"分 → 等率 top-k 保留 27% 的帧 → 混合器决定被丢帧的信息如何补偿 → 压缩后的帧序列送入上层 Conformer。同批次内唯一变量是"检测器 × 混合器"的组合，保证横向可比。

检测器打分原理（判断哪些帧重要）特点
raw在"相邻帧差异曲线"上直接找峰（内容突变点）与谷（平稳点）作为保留候选无平滑，最朴素的对照
savgol先用 Savitzky–Golay 多项式滤波平滑差异曲线，再找峰谷抑制噪声毛刺，更稳
cosine_diff用相邻帧余弦距离替代欧氏差异，距离局部极大（语义边界）与局部极小（平稳段中心）处保留帧Audio Token Compression 风格
cosine_diff+savgol余弦距离曲线先经 Savitzky–Golay 平滑再找峰谷（补全"信号 × 平滑"2×2 网格的最后一格）待跑：与既有口径可比的 3 runs
ple沿累计余弦距离"游走计费"，超过阈值即切段并重置，切段数量不固定DTM-Codec 风格；与等率机制冲突导致崩坏
混合器被丢弃帧的信息如何处理特点
hard（硬选帧）直接按索引取出保留帧，未选帧信息完全丢弃零额外计算，信息损失最大
seg_avg（段均值）每个保留帧替换为其所在段（至下一保留帧之前）全部帧的平均值无参数，丢帧信息以均值形式部分回收
learned（可学习加权）训练一个轻量 MLP，根据局部差异特征预测每个边界处的 Hanning 窗加权系数，对保留帧邻域做加权融合唯一带可训练参数；冠军方案所用

  1. 混合方式是主导因素：soft 混合在全部 3 个正常检测器上战胜硬选帧，平均提升 1.82 个点——"压缩本身不掉分，掉分的是丢帧后不补信息"。
  2. 检测器间差距有限：冠军 cosine_diff（9.15%）与次优 savgol（9.26%）仅差 0.11 个点，最佳前三组合集中在 0.53 个点内——检测器只需"大致合理"，重点在混合方式。
  3. ple 机制性崩坏：其游走分数机制与等率选帧冲突，确认不再投入。

三、当前进行中

  • beam 评测补测已收官：max-pool 9.79%（+0.47pt）、不压缩基线 7.82%，5 组 beam20 全部完成，冠军仍是 cosine_diff+learned 8.79%。
  • LSTM predictor 对照复现（已完成，beam20 8.24% / RTF 0.068）：与旧管线同配方重训（7.85%），未完全复现但优于 attn 冠军 8.79% 0.55 个点；额外发现 LSTM predictor 令 beam 解码提速约 8 倍（RTF 0.068 vs 0.565），是效率叙事的新素材。
  • 检测器 2×2 网格补全（排队中）：cosine_diff+savgol 3 runs，LSTM 复现跑完后自动入队。
  • 质量保障插曲（可备询问）：补测时发现评测脚本存在"配置与模型不匹配不报错"的隐患（strict=False），导致两组中间结果无效。已定位根因、撤销错误数据、按正确口径重跑；已汇报的三组冠军评测均经核实不受影响。后续将在评测入口加架构一致性校验。

四、下一步主攻：泛化研究详细计划（research-plan.md §14）

目标：把 B-matrix 确立的"帧选择带来低损耗的超高计算量缩减（3.7× FLOPs ↓ @ beam 实测 +0.97pt）+ soft 混合制胜"从 Conformer-ASR-100h 单点推向跨架构 / 跨数据规模 / 跨任务，形成顶会要求的泛化证据链。

4.3 执行顺序与决策门

  1. 前置改造：加载器新增 train-clean-460 合并模式 + smoke 门禁。G2 先行（单 run 最长、承载 D2 判据）：写 stage4 队列脚本提队 → G1 跟进（需 squeezeformer 改造 + 冒烟测试）→ G4/G5/G6 穿插填空（G6 需 encoder 支持 2+4+4 布局与双压缩点）→ G3 任务头训练轻量（单 run 1-6h）、G7 推理侧统计，随时穿插；G7 前置核实服务器 MFA 对齐工具状态。
  2. 决策门 D2：460h 上冠军 ≥ max-pool → 泛化故事完整版；否则收缩为"100h 深度机制分析"。决策门 D4：G1 上 soft>hard 复现 → 混合方式结论升级为跨架构结论；否则限定 Conformer 并在 limitations 声明。
  3. 顶会对照：架构 × 数据 × 任务三轴泛化全覆盖（常见底线为三者取二）；消融完整性含位置（G4）/可微（G5）/多级（G6）；机制可解释性由 G7 四件套 + A0 冗余分布承担；单种子口径如实声明；投稿主表 word-WER 由独立工作包承担，效率口径改为 FLOPs/延迟分解并行推进。
