# 460h Phone69 主要计算量评测方案

论文统一比较 corpus PER 与主要 GMAC／输入音频秒。编码器及压缩、实际搜索触发的预测器及 joiner 矩阵运算分列，再报告合计与相对 E09 的比值。位置实验以 E09 的主要 MAC 定义计算量预算。当前研究不再使用 RTF 或重复计时；历史时间记录保留原件。

## 一、冻结输入与比较对象

- 使用 E01–E10 已归档的配置、模型源码、checkpoint 和完整 test-clean 的 2,620 句、19,452.480625 秒音频。主基线 E09 是每帧投影 128 的 stride 4 系统，E01 补充匹配主干宽度。模型按各自选定的 dev-clean checkpoint 打分。已有权重可直接使用。[权威清单](phone69_460h_cpu_authoritative_20261108/README.md)
- 全部保持离线、FP32、batch 1、beam 20。逐句核对音频 ID、参考序列和识别输出。输入清单和模型相同，设备负载可以改变程序完成所需的时间；固定执行路径上的算术计数只取决于形状和搜索分支。日后换软件栈时，连同中间帧数、搜索行数检查数值差异是否改变了执行路径。[固定版本的 beam search](https://docs.pytorch.org/audio/2.8.0/generated/torchaudio.models.RNNTBeamSearch.html)
- 主比较为 E10 对 E09；E02 对 E06 比较早压缩如何改变编码器及候选打分的计算量；E05 对 E10 回答已做 Mel 压缩后增加第 5 层压缩的代价。可选早层单阶段和两处池化等待各自训练完成，采用同一协议和各自独立的记录。

## 二、按真实执行路径计数

对第 $i$ 句记录音频时长 $d_i$ 秒和该句所执行的主要乘加数 $C_i$。正式主表报告

$$
\mathrm{GMAC/audio\text{-}s}=\frac{\sum_i C_i}{10^9\sum_i d_i}.
$$

1 MAC 代表一个乘加。若另列 FLOPs，可将所覆盖的 MAC 乘以 2，并注明约定。分母使用真实音频秒数；句长分组和配对差值也从各组总量计算。该值是处理一秒输入所需的运算量。

| 部分 | 如何计数 |
| --- | --- |
| Conformer 层 | 记录每一层实际执行的张量长度 $T$、宽度 $D$。FFN、Q/K/V/O 投影、逐点卷积和深度卷积按每帧所用的权重矩阵或卷积核大小计数。注意力的两个乘积另计 $2T^2D$。逐句求平方再累加，不能用平均长度的平方代替。 |
| 前后投影与压缩 | 在各自的实际输入长度上计输入／输出投影。对执行的融合 MLP 计矩阵乘法，对相邻帧的余弦点积部分计 $(T-1)D$，对五帧加权和计 $5KD$，其中 $K$ 为该句该阶段的输出数。E08 第一阶段的硬保留不计加权融合。 |
| RNN-T 预测网络与 joiner | 跟踪 beam 20 实际调用预测网络的 token 数、joiner 处理的候选行数和调用次数。逐行计算 LSTM 门、预测投影和 joiner 输出投影的矩阵乘加。用真实搜索分支计数，各系统的输出帧数及展开的候选数都可能不同。 |
| 算术范围 | 主指标涵盖表内乘加。Mel 提取、归一化、softmax、激活、极值比较、top-k、内存访问、Python 控制流等没有统一计入该数。配套报告编码器输出帧数和搜索工作量，并披露这些未计入的操作。该指标用于比较所覆盖的计算量。 |

脚本逐句保留十层长度、主要乘加分项及搜索行数，记录模型配置、checkpoint、冻结清单、计数器和样本索引哈希。每个模型成功后原子写入一个 JSON，重跑时可复用同一条件的完整模型记录。[计数脚本](../scripts/evaluation/measure_phone69_460h_compute.py) · [Conformer 实现](https://github.com/pytorch/audio/blob/v2.8.0/src/torchaudio/models/conformer.py) · [搜索实现](https://github.com/pytorch/audio/blob/v2.8.0/src/torchaudio/models/rnnt_decoder.py)

## 三、先核对 24 句，再扩展到整集

试测从剩余 2,610 句（去掉旧计时预热的前十句）按音频时长分四个等句数组，每组固定抽 6 句，seed 42。所有模型使用相同句子；正式计数包含原清单的全部 2,620 句。正式结果表并列 PER、编码器及压缩 GMAC/audio-s、预测网络及 joiner GMAC/audio-s、合计及相对 E09 的合计比。未完成全量计数的项留空，不以试测数替代。

在仓库根目录使用现有本地冻结的 Python 环境和 OpenMP 路径。原始试测保存在 `pilot24/`。修订版按有效帧长处理压缩、检查单帧旁路，并核对音频、结果完整性及分项总数。第一条命令可在独立目录复现试测，第二条运行整集计数，第三条核验全量结果并生成汇总表。

检查每个配置的逐句输出是否与权威归档一致、每句是否实际经过十个编码层。重复计数应逐句得到相同的整数 MAC。用另一路已有 E05／E10 逐句帧长及解析公式复核相同范围的编码器 MAC。旧公式包含融合 MLP，另外排除了余弦点积、加权和和解码器，比较之前先对齐这些分项。[既有全量编码器核算](../artifacts/research/phone69_460h_summary_20261107/mel_layer5_compute.json)

## 四、全量计数与论文判定

E01–E10 的全量计数均已完成，每组覆盖 2,620 句、19,452.480625 秒音频。E02 对 E06 的编码器与压缩计数由 0.43193 降至 0.29744 GMAC／音频秒，少 31.14%；加入预测器与 joiner 后由 0.62512 降至 0.48637，少 22.20%。[当前全量快照与输入哈希](extremafuse_acl2027/compute_snapshot.json)

主表、图、摘要和相对 E09 的比值均采用已核验的全量结果。候选总 MAC／E09 总 MAC ≤ 1 才满足相同数据及解码协议下的计算量预算。不能沿用旧计时排名判断哪些模型落入该预算。

若要写“达到基线质量门槛时降低计算量”，在查看独立 test-other 前冻结允许的 PER 增加 δ，再用配对说话人区间检验质量门槛，同时报告完整计数的 MAC 比值。若要写“同计算预算下更准”，先在 dev-clean 冻结预算及容忍带，再在独立集确认 PER 差值。当前证据与措辞限定为主要计算量的变化。

计数可重复得到整数结果；GPU/CPU 型号不作为计数公式的输入。仍应冻结模型、输入及软件搜索语义，并核对预测和中间帧数，因为浮点差异可能改变数据依赖的执行路径。小样本计时诊断只作为历史来源记录，不列为论文结果或待办任务。
