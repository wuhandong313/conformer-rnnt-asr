00这个系统在解决什么

先说清楚 RNN-T 的解码瓶颈长什么样，以及为什么直接照搬 LLM 的 Medusa 是不够的。

RNN-T 的 greedy 解码是在一个 (t, u) 二维网格上的单调游走：每一步算一次 joiner(enc[t], g_u)，输出 blank 则 t += 1，输出 label 则 emit 并推进 predictor。整句解码的 joiner 调用次数约为 T + U，而 T（声学帧数）通常是 U（token 数）的几倍——也就是说，绝大部分计算步数都消耗在"什么都不输出的 blank"上。

投机解码的思路很直接：一次 emit 之后，让轻量的 draft head 一口气猜出接下来 K 个 token，再用 verifier（就是 joiner 本身）逐个校验。命中就省下 K 次完整的 joiner 步进。

但 RNN-T 上的 Medusa 比 LLM 上难一个维度。LLM 里 draft 链是纯 token 序列，接受判定是"逐 token 比对"，一维。RNN-T 里 draft 链上的每个 token 还要跨越若干帧（blank-walk），所以接受判定是二维的：不但要猜对 token 是什么，还要猜对 verifier 会在哪一帧把它 emit 出来。

这解释了接受率曲线为什么衰减得这么快：h1 = 0.920，h2 = 0.688，h3 = 0.346。head-1 只需要回答"下一个 token 是什么"；head-3 要回答"再走两段 blank-walk 之后会 emit 什么"——误差在链上 compounding，而且中间的 blank 步数是路径依赖的。

iter-8 最本质的动作，就是把这第二维（时延 δ）显式拆出来单独建模。验证器模拟扫描告诉 head"verifier 会在窗口内的第几帧 emit 出什么"，时延分类器让 head 显式预测"还要等多久"。接受事件从"让 head 隐式地学"变成了"确定性读出 + 显式预测"。

01
无损是硬约束
共享 w_vocab 让 head-0 ≡ verifier；失配时仍提交 verifier 的真实 emit。投机只减少计算步数，不改变输出，PER 恒等于 greedy 基线。

每个新增模块的最后一层投影都 zeros_，step 0 输出恒为 0，与上一轮逐位等价。因此每轮迭代都能从上一轮最优 checkpoint 继续，不会回退。

流式合法

Conformer Encoder、Predictor（2 层 LayerNorm LSTM）、Joiner 全部 requires_grad=False（配置 medusa.freeze_base: true）。Joint 融合是广播加法而非拼接：

原版 Medusa 在 LLM 上工作良好，但直接搬到 RNN-T 会失效，差异有三处：

LLMRNN-T
draft 链纯 token 序列，步距固定为 1token 之间夹着不定长的 blank-walk（0..∞ 帧）
接受判定一维：下一个 token 对不对二维：token 对不对 且 落在哪一帧
验证失败时丢弃 draft，回退到 verifier 分布采样必须提交 verifier 的真实 emit，否则破坏 greedy 等价性

第三点尤其关键。RNN-T 的解码路径是 (t, u) 网格上的一条唯一轨迹，一旦 verifier 在某处 emit 了 p 而你没提交，后续所有状态就全错了。所以 spec_decode.py:251 的处理是：失配时仍把 emitted 提交进输出，然后停止本轮投机。投机只省下步数，不改变结果。

第二点则是接受率衰减的根源，也是 iter-8 要解决的目标：把"落在哪一帧"这个维度显式化。

流式部署只允许 right_context_length=4 mel 帧，除以 time_reduction_stride=4 后只剩 1 个 encoder 帧的未来预算。iter-8 的做法是：窗口宽度保持 9 帧不变（为了 warm-start 保形），但把其中 7 帧从"非法未来"换成"已提交的过去"。

旧布局  (past=0) : [t, t+1, ..., t+8]       # 8 帧未来，流式非法
iter-8  (past=7) : [t-7 .. t-1, t, t+1]     # 1 帧未来，宽度不变

win[b,t] ∈ R^(9×512)  →  flatten  →  context_acoustic: 4608 → 512

实现上是 source[:, :T].roll(p, dims=1) 逐帧移位，越界处（t-p < 0）零填充；推理端 spec_decode.py:161 用 F.pad(enc, (0,0,past-t,0)) 还原完全相同的窗口，训练与推理逐位一致。

为什么这样有效：过去帧在流式部署时免费可得——它们早已被 encoder 处理完并缓存。信息量是净增的，代价为零（这 7 帧对应的音频早已进入系统）。这是 iter-8 三个改动里最稳妥的一个。

draft 被接受的条件不是"猜对 token"，而是"猜对 token 且落在 verifier 的 blank-walk 路径上"。传统做法让 head 隐式地学这件事；iter-8 把它变成确定性读出。

# 训练：从 base-argmax 网格 gather，零额外 FLOPs
base_ids[b,t,l] = argmax_v logits_base[b,t,l]        # detach
ids_k[b,t,l]    = base_ids[b,t, l+k]                 # pad + slice 实现状态左移

prev_start₀ = t
prev_start_k = prev_start_{k-1} + δ_{k-1}   (found 时推进；未命中则原地不动)

for d in 0..4:
    if ids_k[b, prev_start+d, l] != blank and not found:
        sim_id, sim_delta, sim_conf = ids_k, d, conf

推理路径：model.predict_heads 拿到真 encoder 帧窗 [t .. t+1]，逐 head 与其 rolled state 过真 joiner 得到窗口 logits，再走一遍同样的扫描（medusa.py:706-744）。训练用网格近似、推理用真 joiner，两条路径逐步同构。

注意 head-k 的扫描起点是 prev_start_{k-1} + δ_{k-1}——链式的。这复刻了 spec_decode 验证循环里"接受一个 draft 后从它的发射帧继续"的语义，所以三个头扫的是同一条 blank-walk 轨迹上的三段。

设计意图：窗口内的接受事件从"让头去猜"变成"确定性读出"，head 只需学会把这份读出映射到自己的 logits 上。上限取决于窗口覆盖率（found 比例）——scripts/diag_rollout_ceiling.py 就是在量这个天花板，以及它与 oracle 上限之间的差距。

每头一个线性分类器，从 n_k 预测 verifier 对本头 token 的 blank-walk 时延，共 5 个桶：相对偏移 0..per_token_blank-1（= 0..3）+ 1 个 not-found。

为什么用加性调制而不是拼接：因为 w_vocab 是线性层，对时延后验做边缘化「Σ_δ p(δ)·(W·emb_δ)」与「W·(Σ_δ p(δ)·emb_δ)」等价——在隐空间取期望，等价于在 logits 空间取期望，但代价低得多。这是一个很干净的工程技巧。

时延标签 δ_k 来自 sim 扫描的解析结果。它是标签不是输入，所以不违反流式约束：推理时不需要知道未来，只需要分类器自己预测。真正被喂给网络的输入仍然是合法的。

这是让八轮迭代能够连续推进的工程前提，值得单独讲。

每个新增模块的最后一层投影都 torch.nn.init.zeros_，因此它在 step 0 输出恒为 0，整个网络与上一轮逐位等价。于是每一轮都能直接加载上一轮的最优 checkpoint 继续训练，不会有任何性能回退——新模块从"无"开始长，长不出来也不亏。

配套还有两处细节：加载 checkpoint 时会丢弃形状不匹配的 medusa 键（fix(load)），所以改变窗口宽度这类结构性改动也能 warm-start；iter-6 为了保证"位等价"，特意让 context_mlp 保持 iter-4 的原始结构不动，新的深度全部走并行的 extra 路径。

注意第 4 条里"失配仍要 emit"：投机解码在这里不改变 greedy 输出，只改变计算步数。所以 PER 恒等于 greedy 基线（0.073），assert_lossless 就是断言这一点。这也意味着接受率是一个纯粹的加速指标——它掉到 0 也只是没加速，不会让识别变差。

这是 iter-8 最该盯的地方。训练时 _sim_scan_grid 的循环是 for d in range(pb+1)，即向前扫 5 帧（medusa.py:366）；推理时窗口只有 [t, t+1] 两帧，超出部分被 clamp(max=W-1) 截住（medusa.py:727）。

结果是：训练阶段 head 吃到的 sim 特征信息量明显高于推理阶段——found 率会掉、δ 的分布会偏。蒸馏损失是故意利用这种"网格全知"（教头预测窗口外的帧），但 sim 特征本身的训练/推理不一致是被动引入的。

判据：如果 iter-8 跑出来 h1 明显涨、h2/h3 没跟上，优先怀疑这里，而不是继续加深网络。

可能的修法（供参考，未验证）：

  • 训练扫描时按推理窗口截断 max_d = lookahead，让 sim 特征的分布与推理对齐，只保留蒸馏损失去利用网格全知
  • 把 not-found 也作为显式的、带权重的监督信号，让 head 学会"我读不到"这件事本身
  • 对 sim 特征做 dropout：训练时随机丢弃读出，强迫 head 不依赖它，保留兜底能力
